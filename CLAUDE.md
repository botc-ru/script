# Инструкции

## Документация в коде

- При создании компонента пиши над его объявлением TSDoc-комментарий: что делает компонент и как его использовать.
- При правке компонента обновляй этот комментарий, если он устарел.

## Структура кода

- Один файл — одна сущность: компонент, хук, интерфейс или тип. Имя файла совпадает с её именем.

## После завершения правок

1. Проведи рефакторинг и упрости логику.
2. Обнови документацию для компонентов, которые правил.
3. Напиши тесты на новые правки.
4. Прогони все тесты.
5. При успешном прогоне сделай коммит.
